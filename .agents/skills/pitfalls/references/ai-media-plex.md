# Pièges connus — IA vectorielle, Ollama LLM, sous-titres, téléchargements et WebDAV

- **[#1]** **Cold start IA ~30 s** au 1ᵉʳ `/rank` : fastembed télécharge + charge les poids ONNX (cold start documenté `embedding_service.py:11`). Les appels suivants sont rapides (singleton `_model`, lock `_MODEL_LOCK`, `embedding_service.py:71-82`). Override via `AI_EMBED_MODEL` ; cache persistant via `AI_EMBED_CACHE_DIR`.

- **[#2]** **Motifs 503 IA** (contractuels) : **1 garde au niveau du router `/api/ai`** (`verify_api_key`, `deps.py:76-80`) — `AI vector storage unavailable` (sqlite-vec non chargé). ⚠️ **CHANGÉ** : l'ancien 503 `AI service not configured` (AI_API_KEY vide) **n'existe plus** — une clé absente/vide donne désormais **401 fail-closed** (`_authenticate`→False, `deps.py:64-68`), pas 503. **+ 1 motif endpoint** `AI model unavailable` (fastembed KO → `EmbeddingUnavailableError`, sur `/rank` `ai.py:351`, `/rank-multi` `ai.py:450`, `/search`, `/assistant`). **Le motif 503 LLM est distinct** (`_ollama_503`, cf. piège 12). Le garde sqlite-vec s'applique à **TOUS** les endpoints `/api/ai`, y compris LLM pur (cf. piège 12).

- **[#3]** **Épisodes/personnes non supportés par l'IA vectorielle** : ranking au niveau `movie`/`tv` uniquement (`Literal["movie","tv"]`, `ai.py:87,104`). `find_by_imdb_id` ignore défensivement `tv_episode_results`/`tv_season_results`/`person_results` (`tmdb_service.py:281`) → comptés en `resolutionFailed` et droppés.

- **[#4]** **Cap 20 fetches TMDB frais par `/rank`** : `HYDRATE_CAP = 20`, timeout 10 s/tâche (`recommendation_service.py:31-32`) ; le surplus + timeouts + échecs → `cacheMissesDropped` (`stats.dropped`). Le client re-appelle une fois le cache chaud.

- **[#5]** **Le rebuild ne tourne JAMAIS au boot** : uniquement via `POST /api/ai/embed/rebuild` (`embedding_worker.py:3,132`). Idempotent : scan `embedded_at IS NULL`, curseur `tmdb_id > :cursor` (`embedding_worker.py:76`), `PAGE_SIZE=50`, DELETE-puis-INSERT sur `vec0` (UPSERT interdit sur table virtuelle, `embedding_worker.py:108-114`). Jobs en mémoire, `JOBS_CAP=100`.

- **[#12]** **503 LLM Ollama distinct du 503 fastembed** : sur `/describe`/`/chat` (non-stream)/`/assistant`/`/blurb`/`/subtitles`, toute exception Ollama → `_ollama_503` (`ai.py:855`), message `"LLM unavailable — Ollama unreachable or model not loaded"`. NB **couplage à connaître** : ces endpoints sont **aussi** soumis au garde sqlite-vec du router (dépendance module `verify_api_key`, `ai.py:55`) : si sqlite-vec n'est pas chargé, **même les endpoints LLM purs** (`/describe`/`/chat`/`/llm/status`/`/subtitles`) renvoient **503** (`AI vector storage unavailable`) **avant** d'atteindre Ollama, alors qu'ils n'utilisent ni embeddings ni vec0 ; et une clé absente/invalide donne **401** avant tout.

- **[#13]** **Dépendance réseau + cold start Ollama** : `ollama_service` parle à `OLLAMA_URL` (défaut `http://khoj-ollama:11434`, hôte Docker — **injoignable en dev local hors compose**). Timeouts httpx : génération **120 s**, status **5 s** (`ollama_service.py:21-22`). Premier appel = chargement du modèle `gemma4:e4b` en VRAM/RAM côté Ollama (latence). Aucun client SDK : chaque appel ouvre un `AsyncClient` éphémère (pas de pool partagé).

- **[#14]** **SSE chat = pas de 503 propre** : en mode `stream=True`, le flux est déjà ouvert ; une panne Ollama émet `data: [ERROR]\n\n` puis ferme (`ai.py:899-901`), jamais un code HTTP d'erreur. Idem la **reformulation `/search`** et les **explications `/rank`** dégradent silencieusement (jamais de 503). Le client doit gérer ces sentinels.

- **[#16]** **Sous-titres : limites dures** : `/subtitles/translate` rejette `>SUBTITLE_MAX_BYTES` (défaut 2 Mo) ou `>SUBTITLE_MAX_CUES` (défaut 3000) en **413** ; format non SRT/VTT en **422**. Sentinelle de saut de ligne intra-cue ` ⏎ ` (`subtitle_service.py:48`) supposée absente du texte source ; sur mismatch de comptage le chunk garde le texte d'origine (aucune cue perdue/décalée).

- **[#17]** **Feature « Télécharger » (téléchargement physique)** : (a) **worker master-only** — `download_worker.run_drain_loop` ne tourne que sous `if is_master:` (`main.py`, `fcntl` POSIX, piège 7) ; l'enqueue (écriture de lignes `download_job`) marche sur tout worker, mais seul le master draine. (b) **`DOWNLOAD_DIR` vide ⇒ feature no-op** (garde locale au démarrage du worker + service) : rien ne se télécharge tant que le dossier dédié n'est pas configuré dans `.env` (**distinct de `PLEX_LIBRARY_DIR`**). (c) **URL Xtream = secret** : elle contient user/pass, elle est re-dérivée au worker (`stream_service.build_stream_url`) et ne doit **JAMAIS** être persistée en DB, loggée (même `exc_info=True`), ni renvoyée en API/HTML — ne pas régresser. (d) **Confinement d'écriture (F-007)** : toute destination passe par `download_service.resolve_confined` (realpath sous `DOWNLOAD_DIR`) ; **aucun chemin client** n'est accepté — ne pas introduire de `outputDir`-like (dette CR-S01). (e) `download_to_disk` = **`follow_redirects=False`** (anti-SSRF, DL-01) : ne pas réactiver le suivi de redirection. (f) `.part` + `os.replace` atomique + reprise `Range` : ne jamais promouvoir un `.part` sur cancel/échec. Migration **018** (tables `download_job`/`download_batch`).

- **[#18]** **WebDAV `/dav` (feature-gated, no-op par défaut — §5.11)** : (a) **fail-closed 503** tant que `DAV_ENABLED=true` ET `DAV_PASSWORD` non vide ne sont pas réunis tous les deux. (b) **Ne JAMAIS exposer `/dav` via le tunnel/reverse-proxy public** — même app FastAPI, même port que l'API ; **rien dans le code ne l'empêche** : l'exclusion `/dav*` côté ingress est un **prérequis d'activation** (Basic Auth = seule frontière — pas de rate-limit/lockout ; rotation de `DAV_PASSWORD` = **seul** mécanisme de révocation). (c) **Sémaphores de throttle process-local** (`app/dav/throttle.py`) : ne pas passer `uvicorn --workers N>1` (cap upstream multiplié par N — le Dockerfile lance un seul process). (d) **Shim Range** (`DAV_RANGE_SHIM`) : si le panel ignore `Range`, le relay **draine tout le fichier upstream en tenant le permit** → sur un compte `max_connections=1`, un seek Plex bloque toute autre lecture le temps du drain (correctness avant bande passante, acté). (e) rclone ne parle que Basic Auth → ne pas déplacer le router sous `/api`/`verify_backend_secret`. (f) Le logger `httpx` est **épinglé WARNING** (`main.py:104`) pour que les URLs Xtream à credentials du relay ne fuient jamais — ne pas le repasser à INFO. (g) **Jamais de scan Plex sans préchauffage VFS** (`scripts/prewarm-dav-cache.sh`, runbook §0.1/§5.1) : un scan à froid rejoue la cascade `database is locked` côté Plex (transaction tenue pendant l'I/O amont lente) — enchaînement obligatoire = rebuild d'arbre → `rclone rc vfs/refresh` → préchauffage (Plex inactif) → scan. Runbook (rclone/systemd/réglages Plex critiques/rollout par paliers) : `docs/30-ops-plex-webdav.md`.
