- **§5.2 Enrichissement (scraping TMDB)** — au sync, les titres Xtream sont nettoyés par **`clean_title`** (préfixes langue/pays empilés, séparateurs scène `.`/`_`, année parenthésée OU nue, tags qualité partout, crochets). `enrichment_worker.run()` (Phase 1 movies, Phase 2 séries) résout chaque item :
  - **Cache de scrape persistant d'abord** (`scrape_cache_service` + table `tmdb_scrape_cache`, clé `media_type|titre_normalisé|année`) → **0 appel TMDB** pour un même film/série (cross-comptes + survit au redémarrage ; TTL 30 j match / 3 j négatif).
  - Sur miss : **matching façon ScraperMatcher** (`tmdb_service._best_match`) — `titleScore = max(sim(titre), sim(original_title))` (rapidfuzz `max(ratio, token_set_ratio)`), `yearScore` 1.0/0.8/0.5/**0.0** (mismatch = garde-fou homonyme), `confidence = 0.7·title + 0.3·year`, tri `confidence`>`vote_count`. **Auto-match** si `confidence≥0.85` ET `titleScore≥0.90` ET **marge≥0.05** vs 2ᵉ.
  - **Désambiguïsation par résumé** : si doute (marge < 0.05), on départage avec le **résumé Xtream** (`existing_summary`) vs `overview` candidat (`token_set_ratio`, seuils `SUMMARY_MIN_SIM=0.30` / `SUMMARY_TIEBREAK_MARGIN=0.10`).
  - **Fallback** : défaut → sans année → `language=en-US` → `/search/multi`. Le meilleur score est enregistré (`tmdb_match_confidence`) même sans match. Métrique `plexhub_tmdb_match_total{media_type,result}`.
  - **Enrichissement DOUBLE TMDB+OMDb (2026-07-20, design `docs/plans/2026-07-20-omdb-rating-enrichment-design.md`, ADR 0003)** : **un seul** fetch OMDb par média, dans la phase concurrente `_resolve` (sous le `Semaphore(8)` existant, donc l'exigence « toujours fetcher » ne sérialise pas la latence réseau du batch de 200), qui sert **à la fois** le tie-break ci-dessous **ET** l'enrichissement des notes (`_omdb_contradicts` consomme désormais `fr.omdb` pré-fetché, ne fetch plus lui-même). Comportements :
    - **`imdb_rating`/`imdb_votes` systématiques** via OMDb (by-id quand un `imdb_id` est en main — y compris le scénario 3 `existing_imdb` sans TMDB qui récupère quand même les notes), écrits en **COALESCE fill-missing** (ne clobbe jamais une valeur NFO plus riche).
    - **OMDb complète TMDB** : `summary`/`genres`/`cast` manquants remplis en fill-missing.
    - **Repli OMDb-par-titre** sur un vrai `nomatch` TMDB (`fr.from_cache is False` UNIQUEMENT — un `nomatch` en cache est déjà négativement caché côté TMDB, pas de re-scrap ; **pas de nouveau cache titre**). Classification (asymétrie délibérée vs le tie-break — asserter une **nouvelle** identité depuis un titre nu est le risque inverse de *garder* un match) : **discard** si sim<0.60 ; **STRONG** (écrit identité `imdb_id`/`unification_id`/`history_group_key`) si `année-exacte` (garde dure, OMDb renvoie l'anglais) **ET** sim≥0.90 **ET** type cohérent ; **weak** (0.60–0.90, ou année non exacte, ou année absente) → métadonnées+notes seules, **jamais** d'identité.
    - **`display_rating = blend(imdb, tmdb)`** via `rating_blend.blend_display_rating_case(COALESCE(Media.imdb_rating,:new), COALESCE(Media.tmdb_rating,:new), Media.display_rating)` — calculé sur les colonnes durables post-écriture → **reproductible en SQL / self-healing**. `scraped_rating` reste = `vote_average` TMDB (record brut inchangé). Fin de `run()` : `omdb_service.reset_request_count()` + `recompute_display_rating_stmt()` défensif (guérit les clobbers `display_rating` d'un flip `content_hash` sync avant génération+`rebuild_all`).
  - **Tie-break anti-récidive OMDb (2026-07-17)** : avant d'écrire les ids d'un résultat `matched`, (a) tripwire de forme (`imdb_id` doit matcher `^tt\d+$`, `tmdb_id > 0`) et (b) pour les matches à `confidence < 1.0` avec `imdb_id`, downgrade en `ambiguous` (rien d'écrit, statut `skipped`) UNIQUEMENT si année OMDb ≠ ±1 **ET** similarité de titre < 0.55 (garde language-safe). **Fail-open intégral** : budget `OMDB_DAILY_LIMIT` épuisé / OMDb non configuré / not_found / exception → le match est GARDÉ (l'absence de signal ne dégrade jamais le matching, et le résultat TMDB est quand même appliqué). Cache-first via `omdb_scrape_cache_service` + **dédup batch-local des puts** (set `omdb_put_keys` en phase apply — deux items d'un même batch partageant un `imdb_id` ne doublent jamais l'INSERT du cache sous `no_autoflush`, sinon `UNIQUE` → stall permanent).
  - **Backfill OMDb manuel** : `POST /api/admin/enrichment/omdb-backfill` (`verify_master_key`, 202+`jobId`, `enrichment_backfill_worker` any-worker) re-enrichit les médias incomplets (`imdb_id` posé, `imdb_rating` NULL) via OMDb by-id fill-missing + blend (Phase A keyset-paginée, fail-open) ; Phase B optionnelle (`recomputeDisplayRating`) = `recompute_display_rating_stmt()` SQL-only sur tout le catalogue (guérit les lignes déjà complètes mais dérivées, 0 appel réseau).
  - Borné par `ENRICHMENT_DAILY_LIMIT` (défaut **50000**, appels TMDB réels) + `OMDB_DAILY_LIMIT` (défaut **95000**, appels OMDb réels, fail-open), concurrence 8, `MAX_ATTEMPTS=3`. Réf : `workers/enrichment_worker.py`, `workers/enrichment_backfill_worker.py`, `api/enrichment.py`, `utils/rating_blend.py`, `services/tmdb_service.py`, `services/scrape_cache_service.py`, `services/omdb_service.py`, `utils/string_normalizer.py`.
