## Résumé

L'utilisateur de l'app TV, avec l'IA backend configurée, peut faire traduire un sous-titre SRT par le LLM Ollama auto-hébergé. La TV envoie le fichier brut en **un seul appel** ; le backend le découpe en paquets de cues, traduit en parallèle, vérifie l'alignement, reconstruit le SRT (ou le VTT) et met le résultat en cache par empreinte du contenu. Un cron nocturne purge le cache au bout de 30 jours. Persona : spectateur TV (via le lecteur) ; opérateur pour le cache. La capacité n'est atteinte depuis l'UI TV que si l'utilisateur choisit le modèle du fournisseur « backend » (`backend_ollama`) : le modèle par défaut de la TV est un fournisseur cloud (`groq_llama_70b`), qui n'appelle pas ce backend. Côté TV, le format VTT et les champs `sourceLang`, `mediaId` et `ratingKey` ne sont jamais envoyés. **Aucun parcours Maestro ne cible cette capacité** (aucune occurrence de « translat », `backend_ollama` ou `ai_translated` dans `.maestro/` côté TV).

## User stories observées

- **US-BE-15.1** (P1) — En tant qu'utilisateur TV avec l'IA backend activée, je traduis le sous-titre courant depuis le menu « Plus » du lecteur, afin de le lire dans ma langue cible.
  - Parcours : lecteur → menu « Plus » → entrée de traduction du sous-titre → notification « en cours » → piste traduite appliquée · Maestro : aucun
- **US-BE-15.2** (P2) — En tant qu'utilisateur TV, quand j'applique un sous-titre externe téléchargé, il est traduit automatiquement en arrière-plan, afin de ne pas lancer la traduction à la main.
  - Parcours : téléchargement de sous-titres → application → traduction → réapplication du fichier traduit · Maestro : aucun
- **US-BE-15.3** (P2) — En tant qu'utilisateur, je relis un sous-titre déjà traduit sans attendre et sans resolliciter le LLM.
  - Parcours : même contenu, même langue, même modèle → réponse `cached=true` · Maestro : aucun
- **US-BE-15.4** (P3) — En tant qu'opérateur, je veux que le cache de traductions se purge sans intervention, afin de borner l'espace disque.
  - Parcours : cron nocturne sur le processus maître · Maestro : sans objet
- **US-BE-15.5** (P3) — En tant que client API tiers, je traduis un fichier WebVTT ou SRT via l'endpoint. Le backend le permet ; l'app TV n'envoie jamais de VTT.
  - Parcours : appel direct à l'API · Maestro : sans objet

### Formats SRT et VTT

- **FR-BE-575** — Le format est détecté : un contenu qui commence par `WEBVTT` (après BOM et espaces) est du `vtt`, tout le reste du `srt`. `format` peut être imposé à `srt` ou `vtt` (casse stricte) ; toute autre valeur donne 422. — *implémenté* — preuve `app/services/subtitle_service.py:105-116`, `app/services/subtitle_service.py:509-512` · test `tests/test_subtitle_translate.py:260` (VTT auto), `tests/test_subtitle_translate.py:439` (VTT imposé) ; format explicite invalide : aucun
- **FR-BE-576** — SRT : CRLF et CR sont normalisés, les blocs sont séparés par une ligne vide. Une cue = index numérique + timecode + au moins une ligne de texte. Les blocs non conformes (moins de 3 lignes, index non numérique, timecode invalide) sont **abandonnés sans message**. La sortie est **renumérotée 1..N** et les timecodes sont réémis normalisés (fin de ligne parasite retirée). — *implémenté* — preuve `app/services/subtitle_service.py:132-169`, `app/services/subtitle_service.py:172-188` · test `tests/test_subtitle_translate.py:175` (timecodes recopiés ; la source est déjà numérotée 1..2) ; blocs abandonnés : aucun
- **FR-BE-577** — Un BOM en tête de fichier est toléré. — *partiel* (manque : la tolérance ne vaut que pour la détection du format ; `_parse_srt` ne retire pas le BOM, et `str.strip()` de Python ne le traite pas comme un espace, donc l'index `"﻿1"` échoue `isdigit()` et la première cue serait abandonnée ; à vérifier par test) — preuve `app/services/subtitle_service.py:111`, `app/services/subtitle_service.py:142-152` · test : aucun
- **FR-BE-578** — VTT : l'en-tête `WEBVTT`, les blocs `NOTE` et `STYLE`, les blocs sans timecode, les cues vides, l'identifiant de cue et les réglages après le timecode sont réémis à l'identique ; seul le texte des cues est traduit. — *implémenté* — preuve `app/services/subtitle_service.py:205-297` · test `tests/test_subtitle_translate.py:260`, `tests/test_subtitle_translate.py:439`
- **FR-BE-579** — Les sauts de ligne à l'intérieur d'une cue sont encodés par la sentinelle ` ⏎ ` avant l'envoi au LLM, puis restaurés. Les balises inline (`<i>`, `<b>`, `{\an8}`) ne sont protégées que par une consigne du prompt : aucun contrôle dans le code. — *implémenté* — preuve `app/services/subtitle_service.py:48`, `app/services/subtitle_service.py:326-354`, `app/services/subtitle_service.py:389-400` · test `tests/test_subtitle_translate.py:385` (faux LLM en écho : prouve l'aller-retour, pas la fidélité d'un vrai modèle)
- **FR-BE-580** — Tout autre format (ASS/SSA, texte libre) est lu comme du SRT, produit 0 cue et donne 422. — *implémenté* (comportement constaté) — preuve `app/services/subtitle_service.py:114-116`, `app/services/subtitle_service.py:520-521` · test `tests/test_subtitle_translate.py:289` (texte libre) ; ASS : aucun

- **FR-BE-583** — Alignement strict : les numéros lus dans la réponse du LLM doivent être exactement {1..n}. ## Règles métier

- **RG-BE-15.1** — Clé de cache = SHA-256(contenu brut, `targetLang`, `format` ou vide, `sourceLang` ou vide, `OLLAMA_MODEL`). Deux contenus qui diffèrent d'un octet (fin de ligne, espace) ou deux écritures d'une même langue (`fr`, `French`) donnent deux entrées. — preuve `app/api/ai.py:961-972`
- **RG-BE-15.2** — Aucune cue n'est perdue ni décalée par la traduction : numéros exactement {1..n}, un essai de plus, puis repli sur l'original du paquet. La garantie ne couvre pas les blocs SRT malformés, abandonnés au parsing. — preuve `app/services/subtitle_service.py:147-156`, `app/services/subtitle_service.py:361-386`, `app/services/subtitle_service.py:456-460`
- **RG-BE-15.3** — Limites dures : 2 000 000 octets UTF-8 et 3000 cues donnent 413 ; format inconnu ou sans cue donne 422. — preuve `app/services/subtitle_service.py:498-527`, `app/config.py:212-213`
- **RG-BE-15.4** — Délais : 120 s par tentative de paquet avec repli sur l'original, 600 s pour l'ensemble avec 503. Les erreurs de transport HTTP donnent 503, sans repli. — preuve `app/services/subtitle_service.py:430-454`, `app/services/subtitle_service.py:547-557`, `app/api/ai.py:1007-1014`
- **RG-BE-15.5** — La sentinelle ` ⏎ ` est supposée absente du texte source. La restauration reconnaît le glyphe seul, avec ou sans espaces autour, et retire les blancs de bord de chaque cue. — preuve `app/services/subtitle_service.py:48`, `app/services/subtitle_service.py:389-400`
- **RG-BE-15.6** — SRT : sortie renumérotée 1..N. VTT : en-tête, NOTE, STYLE, identifiants et réglages de cue conservés tels quels. — preuve `app/services/subtitle_service.py:172-188`, `app/services/subtitle_service.py:282-297`
- **RG-BE-15.7** — La rétention se compte depuis la création de l'entrée, pas depuis sa dernière lecture ; une rétention ≤ 0 conserve tout ; la purge ne tourne que sur le maître. — preuve `app/services/subtitle_service.py:615-624`, `app/main.py:328`
- **RG-BE-15.8** — La langue cible est une chaîne libre (défaut `fr`), ni normalisée ni validée, recopiée dans le prompt et dans `target_lang`. — preuve `app/api/ai.py:930`, `app/services/subtitle_service.py:342-354`
- **RG-BE-15.9** — Activation côté TV : réglage actif ET modèle backend ET IA backend configurée. Sinon la piste d'origine est conservée sans erreur et sans appel réseau. — preuve `tv:data/src/main/java/com/chakir/plexhubtv/data/repository/SubtitleTranslationRepositoryImpl.kt:68-71`, `tv:data/src/main/java/com/chakir/plexhubtv/data/repository/SubtitleTranslationRepositoryImpl.kt:106-113`
